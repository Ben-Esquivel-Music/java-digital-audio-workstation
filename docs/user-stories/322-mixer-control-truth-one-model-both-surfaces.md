# Mixer Control Truth: One Model, Both Surfaces, Nothing Dead

## Motivation

The mixer panel's own fader/pan/mute/solo strips are live — they write the `MixerChannel` state the render path reads (`Mixer.java:663`, `:683`). Almost everything around them half-lies:

- **Arrangement track strips write a model the engine never reads.** Volume (`TrackStripController.java:371`), pan (`:385`), mute (`:434`), and solo (`:451`) write only `Track`; nothing on the render path reads `Track` state and no bridge exists. The story-291 registry/binder that would unify the two surfaces is constructed only in tests — `rebuildViewModels()` builds Project/Transport/History VMs only (`MainController.java:482`). Muting a track in the arrangement changes a highlight and nothing else.
- **The VCA fader is inaudible.** `VcaGroupManager.effectiveLinearMultiplier` (`VcaGroupManager.java:247`) is RT-safe, documented as "queried by RenderPipeline", and called by nothing — `mixDown` uses raw `channel.getVolume()` (`Mixer.java:683`). `VcaStrip` mute/solo write `MixerChannel` only (`VcaStrip.java:198`, `:203`), so `Track` and the arrangement silently diverge.
- **Master and return pan sliders are dead** — the summing stages apply volume only (`Mixer.java:740‑762` returns, `:770‑780` master) while the sliders write `setPan` (`MixerView.java:1653`, `:2276`) that nothing reads.
- **The legacy SEND slider is a dead sink**: `setSendLevel` (`MixerView.java:1463‑1470`) feeds a four-argument aux `mixDown` overload (`Mixer.java:536‑596`) with no production caller — the live path is the return-bus overload (`RenderPipeline.java:463`). The SEND_LEVEL automation lane writes the same dead field.
- **Snapshot/A‑B recall changes audio but not visuals.** `recallSlot`/`toggleAB` (`MixerView.java:536`, `:568`) sync only the slot buttons; strip sliders keep pre-recall positions, and because the fader listener writes the model on any value change, **nudging a stale fader silently overwrites the recalled scene** — a session-corrupting trap.
- **Mute/arm highlights are not seeded from the model** — styles are applied only inside the click handler (`MixerView.java:1226‑1234`, `:1268`), so every strip rebuild shows muted/armed channels as inactive while the audio stays muted/armed.
- **Decorative or dead affordances**: the "3D" button opens a standalone spatial panner attached to nothing (`MixerView.java:1294`); the stereo-link "Link Inserts"/"Link Sends" checkboxes store flags no code consumes (`ChannelLinkPopover.java:95‑97`); the arrangement strip renders a hardcoded Gain/Gate/Comp/HPF/Limiter insert chain regardless of the rack (`TrackStripController.java:393` — "placeholder inserts" by its own comment); the per-track input-device dialog stores a choice (`:339‑341`) that recording honours only for the first armed track (`TransportController.java:452‑457`); and the story-271 `MixerChannelStrip` suite — the intended future strip — has no production instantiation, so the Inspector's listeners for its selection events can never fire (`InspectorDrawer.java:269‑270`).

For a studio engineer, the mixer is usable only for basic moves made from the mixer panel itself; every mirrored or adjacent control is a coin-flip between "does nothing" and "silently corrupts the scene".

## Goals

- **One intent path, both surfaces**: arrangement strip mute/solo/volume/pan drive the same channel-intent path as the mixer strips — the story-291 `TrackVM`/`ChannelVM` registry/binder is finally constructed in production (`rebuildViewModels()`), dual-writing `Track` + `MixerChannel` in one place. The dead `Track`-only writes die; mute in either surface mutes the audio and moves both visuals.
- **VCA gain reaches the render path**: `effectiveLinearMultiplier` is factored into channel gain and post-fader sends in the render path (subsuming the engine half of existing story 153 — VCA Groups); VCA mute/solo dual-writes `Track` through the same intent path so the arrangement stays consistent.
- **Master and return pan go live** with a constant-power pan law in the summing stages.
- **Removal arm for the legacy send path** (binding decision): the per-strip SEND slider and the dead four-argument aux `mixDown` overload are **removed**, and SEND_LEVEL automation is **retargeted** at real per-send levels on the live multi-bus path.
- **Snapshot/A‑B recall re-seeds strip visuals** from the model after recall (and undo), so a stale-fader nudge can only ever change the fader you touched.
- **Mute/arm/solo styles seed from the model** on every strip build/rebuild.
- **"Link Inserts" is removed** (no plugin-clone contract exists to honour it); **"Link Sends" is wired** to mirror send-level changes across a linked pair.
- **Per-track input-device choices become a session-level input selection** with visible mismatch warnings when per-track choices disagree; full multi-device capture routing is explicitly deferred to Book 2's story 326.
- **The 3D panner button is hidden** until a spatial node exists in the channel's chain.
- **Strip insert indicators render the channel's real `InsertSlot` list** (names and bypass state, updating on rack edits) — the hardcoded five-icon fiction is replaced.
- **The deferred story-271 `MixerChannelStrip` migration completes as a pure skin swap** in (or immediately after) this story, once the facts flow through `ChannelVM`; the dead strip suite must not survive uninstantiated.

## Goals — Tests

- **Cross-surface mute/solo/volume/pan test**: changing any of the four in the arrangement moves the mixer strip and audibly changes the rendered block (and vice versa), via the shared VM intent path.
- **Model-write conformance test** (the repo's source-scan sentinel pattern): fails on any strip control writing a model the render path does not read — the structural guard that keeps §5.6 true.
- **VCA audibility test**: a VCA fader change scales member channels' rendered output through `effectiveLinearMultiplier`, including post-fader send contributions; a 0-multiplier group silences members.
- **VCA dual-write test**: VCA mute/solo updates `Track` and the arrangement strip visuals as well as `MixerChannel`.
- **Pan-law test**: master and return pan apply constant-power panning in the summing stage (center = equal gain, hard-pan within the law's tolerance).
- **Send retarget test**: the aux `mixDown` overload and SEND slider are gone (source scan); a SEND_LEVEL automation lane now writes a per-send level that measurably changes return-bus audio.
- **Recall re-seed test**: recall snapshot B — every strip visual matches the recalled model; nudge one fader — only that channel's value changes (no silent scene overwrite).
- **Style-seed test**: rebuilding strips over muted/armed/soloed channels renders the active styles without any click.
- **Link Sends test**: on a linked pair, a send-level change mirrors to the partner; the "Link Inserts" control no longer exists (source scan).
- **Input-selection test**: the session-level input selection is what arming consults; conflicting per-track choices surface a visible mismatch warning rather than being silently ignored.
- **3D visibility test**: the panner button is absent/hidden for channels without a spatial node.
- **Insert-indicator truth test**: indicators reflect the real rack (add/remove/bypass updates them); the hardcoded placeholder list is gone.
- **Strip-suite liveness test**: `MixerChannelStrip` is instantiated in production and the Inspector's selection-event listeners fire on strip selection — no dead suite remains.

## Resolution

Every audible mixer control now writes the model the engine reads, through one intent path, on every surface. A per-project-generation `TrackControlWiring` — a live `TrackChannelRegistry` (one `TrackVM`/`ChannelVM` per track, track channel, return bus and the master) plus one command sink (`CoreTrackIntentHandler` wrapped by `LinkedTrackCommandDispatcher`) — is built by `MainController.rebuildTrackControlWiring()` before either surface's strips exist and handed to `MixerView`, `TrackStripController` and `PerformanceStageView` as a live supplier. The arrangement strip's volume/pan sliders and mute/solo/arm buttons, the mixer's track strips (now `MixerChannelStrip`, bound by `TrackControlBinder.bindStrip`), the return and master strips (`ChannelControlBinder`), the VCA strip's mute/solo, the Performance Stage tiles (`TrackControlBinder.bindTile`) and the strip's inline rename all raise a sealed `TrackCommand`; only the handler mutates, dual-writing `Track` + `MixerChannel` with a per-surface VALIDATE so a diverged pair heals on the next intent. Stereo-link mirroring moved out of `MixerView`'s widget maps into the dispatcher (partner channel via `ChannelLinkManager`, partner `Track` via the handler's Track-only heal); the `propagate*`/`propagationSuppressed` machinery is gone. The dead `Track`-only writes in `TrackStripController` and `PerformanceStageView` no longer exist, and the session-import seed (`SessionInterchangeController`) writes both models in one place. As the RT precondition for a live registry, `MixerChannel`/`Track` setters notify only on change, and `ChannelVM` publishes VOLUME/PAN off the FX thread through the wait-free continuous channel (never `Platform.runLater` from the render thread).

In the engine, `Mixer` resolves each channel's composite gain once per block — fader × `VcaGroupManager.effectiveLinearMultiplier` — in `mixDown`, `mixDownInstrumented` and `renderDirectOutputs`, and passes it into channel summing and post-fader sends (pre-fader/pre-insert sends stay fader-independent). Return-bus and master pan are live through the new `PanLaw`. **Binding decision — bus pan law:** buses use the unity-at-centre constant-power taper (`L = min(1, sqrt(2)·cos θ)`, `R = min(1, sqrt(2)·sin θ)`, `θ = (pan+1)·π/4`): centre is exactly (1, 1) so every never-panned bus renders bit-identically to the pre-322 volume-only output, hard pans reach (1, 0)/(0, 1), the attenuated lane follows the constant-power curve, and a bus never exceeds its fader gain. The raw −3 dB-at-centre channel law was rejected for buses because it would have dropped every existing project's master by 3 dB on upgrade; the channel law itself is untouched. **Binding decision — send path:** `MixerChannel.sendLevel`, the four-argument aux `mixDown` overload and the per-strip SEND slider are removed, not wired; `SEND_LEVEL` automation now writes the level of the channel's `Send` whose target is the first return bus (`Mixer.getAuxBus()`, the bus the enum always named) and is inert when no such send exists; mixer snapshots capture per-send state keyed by target bus (level + tap) and restore by target, tolerating legacy `send-level` attributes on read.

Snapshot/A-B recall re-seeds structurally — every strip control is a VM subscriber — and `MixerView.healTrackMirrorsFromChannels()` re-asserts each track channel's state through the intent path after recall, toggle A/B and their undo, so the `Track` mirrors (and both surfaces' TrackVM-bound buttons) follow a channel-only `MixerSnapshot`; nudging a fader after recall changes only its own channel. Mute/solo/arm styles are seeded from the model at bind time as `:active`/`:muted`/`:soloed`/`:armed` pseudo-classes with token CSS (the inline hex `setStyle` calls are gone; solo-safe is the `:solo-safe` pseudo-class). **Binding decision — stereo link:** "Link Inserts" is removed from `ChannelLink`, the popover and the project file (the attribute is tolerated on read) because no plugin-clone contract exists to honour it; "Link Sends" is wired through `ChannelLinkManager.applySendChange`, so a send level or tap edit on either member mirrors to the partner's send for the same bus (created if absent) with a stateless echo guard. **Binding decision — input device:** `SessionInputSelection` (interface; production `SettingsBackedSessionInputSelection`) is the one session-level input: the per-track dialogs preselect it and select it (persisted to settings and applied through `AudioEngineController` on a virtual thread) *(story 326 later reversed this: a per-track pick sets only that track's input-device identity, and `SessionInputSelection.select` was removed)*, the per-track index is kept for story 326, and a single WARNING — "Recording uses the session input '<S>'; track(s) A, B chose '<D>' — multi-device capture is story 326" — is shown on arm and at record start whenever an armed track's choice disagrees *(story 326 retired this warning: capture resolves each armed track's own input-device identity through the routing union, refusing at arm and record start what it cannot honour, and `SessionInputSelection.mismatches` and `mismatchWarning` were removed)*; full multi-device capture stays with Book 2's story 326.

The 3D panner button's `visible` and `managed` are bound to `ChannelVM.spatialNodePresent`, derived from the channel's real insert list via the first production use of `@ProcessorCapability` (`ProcessorCapabilities.SPATIAL` on every `AudioProcessor` under `core.spatial`, read through the per-class-cached introspector, never on the audio thread). Strip insert indicators render `ChannelVM.inserts` (name, bypass) for every track type; the Gain/Gate/Comp/HPF/Limiter fiction and the MIDI instrument hints are deleted. **Skin-swap scope:** the deferred story-271 migration is complete for the mixer's *track* strips — `MixerView` instantiates one `MixerChannelStrip` per track (channel id, name, M/S/R, fader in dB, pan, inserts and the VM-owned meter all bound through `bindStrip`), so the Inspector's `INSERT_SELECTED`/`SEND_SELECTED` forwarding is live (keyed on the event target, since JavaFX re-sources events per node). The strip's `sendsProperty` is deliberately left empty because its skin's send fader has no write-back and a fed row would be a dead control — the hand-built per-return send rows (with Link Sends) and cue sends remain host siblings, as does the `InsertEffectRack`. The return, master and VCA strips keep their hand-built layout and the `.mixer-channel` alias (`.mixer-fader` on the hand-built send/cue sliders) as remaining story-271 debt. The strip's double-click inline rename, made reachable by the swap, now raises `RenameTrackCommand` (Track-only — a `MixerChannel`'s name is fixed at creation) instead of dying in the strip's own property; `MixerView` records it as one undo entry, the arrangement lane's label follows `TrackVM.name`, and Escape cancels the edit without a commit (fix round 1).

`MixerControlTruthScanTest` is the structural guard: a source scan over `daw-app/src/main` that fails on any `setVolume`/`setPan`/`setMuted`/`setSolo`/`setArmed` whose receiver resolves to a `Track` or `MixerChannel` — directly, unwrapped out of a collection or `Optional`, on a getter chain or an in-file model-returning method, through a `var` initialised from any of those, on an enhanced-for `var` over a typed receiver or a model source (a getter chain or an in-file model-returning method), through a `requireNonNull(...)` wrapper around a getter chain or an in-file model-returning method — bound to a `var` or used inline as the receiver; `Objects.`-qualified, `java.util.Objects.`-qualified or static-imported; with no second argument, a message or a `Supplier` — on a lambda parameter — bare, parenthesised or `var`-typed — bound through any `stream()`/`filter(...)`/`subList(...)` segments, or as a method reference, type-qualified (`MixerChannel::setMuted`), bound to a typed identifier (`track::setMuted`) or bound to a model getter chain or in-file model-returning method (`project.getMasterChannel()::setMuted`) — outside an allow-list of non-control writers keyed by source path: `CoreTrackIntentHandler` (the intent path itself) and the `applyMixerSettings` body of `SessionInterchangeController` (a persistence-shaped seed of a freshly imported track's mirrors; a site elsewhere in that file is an offender). It additionally pins that no `setSendLevel`/`getSendLevel`, no "Link Inserts", and no placeholder-insert fiction survive, that `MixerView` instantiates `MixerChannelStrip`, and that its 3D button is gated rather than shown. Its non-vacuity guards require the intent path's own dual-write sites to be found and every allow-list entry to still have a site inside its scope, and a self-check feeds one fixture per receiver shape (positives and negatives) through the same helpers — the permanent fault-injection fixtures.

**Fix round 1.** Six read-only verification lenses and a fault-injection prober read the story tree before it was committed. What they found, and what changed: *RT-thread identity* — `Platform.isFxApplicationThread()` reaches `Toolkit.getToolkit()`, a `static synchronized` method, so every call from the render thread took the `Toolkit` class monitor (design book §6.1: the RT callback never locks); the VM layer now asks `FxDispatcher.isFxThread()` — a volatile field compare against the thread `start()` recorded and every pulse re-asserts — and `ChannelVM`'s VOLUME/PAN republish is allocation-free (no capturing lambda; the continuous channel is the only escape) while MUTE/SOLO/INSERTS hand pre-allocated runnables to the FX marshal; a source scan over `ui/vm` + `ui/marshal` and a Class-File-API bytecode walk from `ChannelVM.onCoreChange` pin both. *SEND_LEVEL with no return bus* — a lane rendered against a mixer whose every return bus had been removed threw `IndexOutOfBoundsException` out of `Mixer.getAuxBus()` on the render thread; `RenderPipeline.applyAutomation` now checks `Mixer.getReturnBusCount()` first (size-then-index, no allocation) and the lane is inert. *Session-device re-selection* — confirming a per-track input dialog on the preselected session device re-applied the audio configuration (stopping the transport and reopening the stream); `SettingsBackedSessionInputSelection.selectAndApply` returns `Optional<Thread>` and is a no-op for the device whose qualified name already is the session name (the gate was bare-name tolerant until fix round 2), and both mismatch checks (arm, record start) enumerate devices on a virtual thread and marshal only the comparison (over the FX-owned track list) and the WARNING to the FX thread. *Undo* — a mixer-strip rename recorded no entry and a linked pair's send drag or tap edit undid only the dragged side; `MixerView` records the strip's `RenameTrackCommand` as one `UndoableAction` and executes one compound entry (source + partner) for linked send edits, re-seeding every send row from the model on each history event. *Recall while off-screen* — a snapshots-panel recall undone while the Mixer was detached left the `Track` mirrors stale; the panel's entry heals in `execute()` and `undo()` and a `MixerView` returning to the scene catches up. *Smaller* — the arrangement lane's name label follows `TrackVM.name` while bound; Escape cancels the strip's inline name edit; production `MixerView`s are constructed over the host's wiring (no standalone wiring or double strip build); `CoreTrackIntentHandler.setVolume`/`setPan` announce a `MixerEvent` only when the channel changed; the return-pan cases of `BusPanLawTest` also drive `mixDownInstrumented`; and the model-write sentinel resolves method references, `var` receivers, enhanced-for `var`, in-file model-returning methods, stream/filter segments and `Optional` unwraps — the prober's injected leaks the first scan missed — with its allow-list keyed by source path and the session-import entry scoped to `applyMixerSettings`.

**Fix round 2.** Three review lenses and a fault-injection prober re-read the tree after round 1 — the prober's nine required one-line faults were each caught by a named test (plus an extra persist-before-return fault against the session-input gate), and three of its probes stayed behind as permanent contract tests — `Story322SessionInputUpgradeContractTest`, `Story322SendReleaseGuardContractTest` and `Story322LivePulseOnlyPublishContractTest` (the round-1 prober had kept two, `Story322LinkedSendUndoContractTest` and `Story322RecordedFxThreadPublishContractTest`). What the lenses found, and what changed: *Session-input gate* — the round-1 no-op used `isSessionDevice`, whose story-316 bare-name tolerance also accepts a same-named device under another host API, while the per-track dialogs' callers still wrote the track's input index, the status bar and the dirty flag — the silent ignore §5.6 forbids; `SettingsBackedSessionInputSelection.selectAndApply` now returns empty only when `device.qualifiedName()` equals the persisted session name exactly, so a legacy bare name upgrades itself on the first confirm (one persist, one apply) and a differently-qualified pick persists and applies, while `isSessionDevice`, preselection and `mismatches` keep the tolerance. *Phantom rename entry* — a strip rename differing from the track's name only by surrounding whitespace was VALIDATEd idempotent by the handler yet still pushed a `Rename Track: Kick → Kick` entry and cleared the redo stack; `RenameTrackCommand` now owns the strip rule (`normalize`, `normalizedName()`, `changesNothing()`), `CoreTrackIntentHandler.renameTrack` validates through it, and `MixerView.undoableRenames` hands a command that changes nothing straight to the sink (no entry, redo kept; a blank name keeps the wrapped path, where the handler's throw prevents the push). *No-op send release* — a press and release on a send slider without a move executed `SetSendRoutingAction` for the source and, on a linked pair, the partner, creating a 0.0 send on both members that a SEND_LEVEL lane would then drive; the release handler now compares the live `SendState` (present, level, tap) of the source and of the partner resolved at press with the pre-drag capture and returns before any restore, step or entry when neither moved, so a click without a move or a drag back to its start creates nothing. *Switch map off the RT path* — `ChannelVM.onCoreChange`'s enum `switch` compiled to a `ChannelVM$1.$SwitchMap$…` lookup whose class initialiser (an `int[]`, a `values()` clone, the class-init lock) runs on the first signalling thread, which after a fresh JVM can be the render thread; the method now dispatches by identity compare on the `ChangeKind` constants — no synthetic class exists — and the bytecode sentinel fails on any `$SwitchMap$` field access or any access into a synthetic `ChannelVM$<n>` class, a rule proven to fire by a fixture that switches on the real `ChangeKind` (a nested enum would not do: javac lowers a switch over an enum from the same compilation unit to a direct `ordinal()` switch with no synthetic class). *Pins* — nothing had pinned `FxDispatcher.isFxThread()` itself (a `Platform`-only body answers every round-1 test identically), so a Class-File-API test now requires its `getfield fxThread`, its `Thread.currentThread()` compare, exactly one `Platform.isFxApplicationThread()` behind a null-check branch and no monitor, allocation or `invokedynamic`; the model-write sentinel additionally resolves bound method references (`track::setMuted`), `var` locals through `Objects.requireNonNull(...)`, parenthesised single lambda parameters and `subList` segments — one positive and one negative fixture each — and the production scan flags nothing new. *Prose* — the arm and record-start mismatch checks marshal the comparison over the FX-owned track list as well as the WARNING back to the FX thread, and their Javadocs and this document now say so.

**Fix round 3.** Two review lenses and a fault-injection prober re-read the round-2 tree; their findings were in the two sentinels and in this document, so the round is test-only: `FxDispatcherFxThreadBytecodeSentinelTest` now maps every label to the instruction it precedes and collects every jump (branch, switch case and default, exception handler), and requires exactly one volatile read of the field (one `getfield fxThread` — fix round 5: the local-free `if (fxThread == null) { return Platform.isFxApplicationThread(); } return Thread.currentThread() == fxThread;` reads it twice and fails, the two instruction indices named) and the one `Platform.isFxApplicationThread()` to be reachable only through the null check on the recorded field, on its null edge (an `ifnull` taken, or an `ifnonnull` fallen through — fix round 5: rounds 3 and 4 accepted either opcode on either edge, so `boolean same = Thread.currentThread() == recorded; if (recorded != null) { return Platform.isFxApplicationThread(); } return same;` and `return recorded == null ? same : Platform.isFxApplicationThread();` — the toolkit entered on the recorded branch, the monitor on every render-thread call — passed; both now fail, the opcode found named), in one of two shapes — the ternary shape: the instruction before it an unconditional transfer (`goto`, any `*return`, `athrow`), so it is never reached by fall-through, and exactly one jump landing on it, that jump an `ifnull`; or the early-return shape (`if (recorded == null) { return Platform.isFxApplicationThread(); }`, fix round 4): no jump landing on it and the instruction before it an `ifnonnull`, whose fall-through edge is its only way in — and, in either shape, the qualifying null check must test the recorded field itself, the instruction before it being the `getfield fxThread` or an `aload` of the slot the `astore` right after that read fills (fix round 4: a derived local — `Thread probe = … ? recorded : null; return probe != null ? true : Platform.isFxApplicationThread();` — passed every round-3 rule and fails here, the offending instruction named) — which the order-green fall-through body `if (recorded != null && Thread.currentThread() == recorded) return true; return Platform.isFxApplicationThread();` (the `Toolkit` monitor on every render-thread call) fails on its second, `if_acmpne`, jump; and it walks the same-class callees of `isFxThread()` in the `ChannelVmRtPathBytecodeSentinelTest` idiom, requiring exactly one toolkit invoke across the reached set, in `isFxThread()` itself, and no monitor, allocation or `invokedynamic` anywhere in it — which a `private static boolean toolkitAgrees()` helper calling `Platform.isFxApplicationThread()` on the recorded-thread branch (green under every earlier test) fails, the reached set named in the message — the callee-following itself proven on a nested `WalkFixture` whose `isFxThread()` calls a same-class `helper()` that enters the toolkit: the walk must reach exactly both methods and record both toolkit entries (`FxDispatcherFxThreadBytecodeSentinelTest.theWalkFollowsSameClassCalleesOnAFixtureWithAToolkitHelper`, fix round 4; the production reached set is the root alone, so no green run had followed a callee). The model-write sentinel additionally resolves method references bound to a model getter chain or to an in-file model-returning method (`project.getMasterChannel()::setMuted`, `resolveChannel(id)::setMuted`), `requireNonNull(...)` used inline as the receiver (`Objects.requireNonNull(project.getMixerChannelForTrack(t)).setVolume(…)`, static-imported with a message, or around an in-file model-returning method), the package-qualified `java.util.Objects.requireNonNull` behind a `var`, `var`-typed lambda parameters (`forEach((var t) -> …)`) and the `requireNonNull(T, Supplier<String>)` overload's message — one positive fixture each and a negative twin where the shape has one, the production scan flagging nothing new — while a two-parameter lambda over a `Map` of model values (`byId.forEach((id, t) -> t.setMuted(true))`) is a documented boundary: it is not typed.

**Copilot review round (PR #977, 2026-09-27).** Three Medium findings, each confirmed against the code before it was fixed. *Unresolvable per-track index* — `SessionInputSelection.mismatches` skipped an armed track whose persisted `input-device` index (written by `ProjectSerializer`, restored by `ProjectDeserializer`) resolved to no enumerated device, documenting it as "dangling, not a disagreement"; after unplugging an interface a reopened project may hold such indices (after a backend change a stale index may instead name an unrelated device that now carries it — treated as a choice of that device, reported only when that device is not the session device, since only the bare int is persisted), and recording then used the session input with no warning — the silent ignore §5.6 forbids. ### Known limitations and deferrals

- Return-bus UUIDs are not persisted (Book 3), so snapshot sends are written with both the target id and the bus index and resolved by index on load; return-bus link and VCA membership still do not survive a reopen (pre-existing).
- `MixerViewSnapshotTest` self-skips on the development machine, so its goldens were not rebaselined although the mixer layout changed (the 3D button hides; a `MixerChannelStrip` replaces the slider + meter stack) — rebaseline with `-Dsnapshots.update=true` where that test renders.
- Undo coverage: mute/solo/volume/pan gestures record no undo entry on either surface (pre-existing — `SetVolumeAction`/`ToggleMuteAction` have no production caller). A mixer-strip rename and a linked pair's send drag or tap edit are one entry each (fix round 1); the arrangement's inline rename keeps its own `UndoableAction` that writes the `Track` directly instead of raising `RenameTrackCommand` — both labels follow `TrackVM.name` either way.
- Channel-only undo entries and the `Track` mirrors (fix round 1): the snapshots panel's recall, `recallSlot` and `toggleAB` heal inside their own entries (`execute()` and `undo()`), and a `MixerView` that returns to the scene after a detach catches up (`onUndoHistoryChanged`) because its history listener is released while it is off-screen. Any future channel-only `UndoableAction` that can be undone while the Mixer is off-screen must heal the same way — or the history heal moves from the view to the per-generation wiring.
- `MixerView.healTrackMirrorsFromChannels()` runs on every history event and is O(tracks²) (`DawProject.getTrackForChannel` is a linear scan per channel) — negligible at session sizes; a reverse index is the follow-up if history events ever become frequent.
- Two pre-existing refresh-inside-a-listener patterns remain: the story-137 `armRefresh` in `MixerView.bindTrackStrip` calls `refresh()` from inside the `TrackVM.armed` notification, and a VCA fader release rebuilds the member strips just to refresh the "VCA: <name> (<gain> dB)" badge readout (javafx-application-design §13).
- `StyleSeedTest`, `ArrangementStyleSeedTest` and `RecallReseedTest` assert pseudo-class state only; the token CSS selectors behind `:active`/`:muted`/`:soloed`/`:armed`/`:solo-safe` are not exercised under a realised skin (headless CSS pitfalls).
- At record start the mismatch WARNING lands on a later FX turn than the "Recording started" INFO pill and supersedes it (only while the take is still confirmed — an aborted take's ERROR is never covered by it).
- Phase invert stays a direct `Track` write in the arrangement strip: `MixerChannel` has its own `phaseInverted` flag (captured by `MixerSnapshot`, read by `RenderInPlaceService`) but neither `Mixer` nor `RenderPipeline` reads either flag on the live path and `ChannelVM` has no phase slice — the dual-write is a flagged follow-up adjacent to §5.6.
- A Performance Stage left active across a project load keeps the previous generation's tiles (pre-existing).
- The story-137 `InputMeterStrip` beside an armed track's strip keeps its 10 × 120 px size next to the taller `MixerChannelStrip` (cosmetic).
- `PerformanceStageView` built without a wiring (its three-argument constructor, pure-unit contexts) disables the tiles' M/S/R rather than binding them.
- Outside this story (pre-existing, flagged): no production path re-adds the arrangement strips for the tracks of a project loaded from disk (`ProjectLifecycleController.rebuildUI` and the snapshot-restore path rebuild only the "TRACKS" header); the mixer surface is unaffected.
- Structural mixer edits are not serialised against the render thread (pre-existing): `Mixer.returnBuses` and `MixerChannel.sends` are plain `ArrayList`s that `Mixer.removeReturnBus` (the return strip's remove button, `RemoveReturnBusAction`) and `addSend`/`removeSend` mutate on the FX thread, and the SEND_LEVEL guard in `RenderPipeline.applyAutomation` reads `getReturnBusCount()` and then `getAuxBus()` (= `returnBuses.get(0)`) — the same size-then-index window `mixDown` and `mixDownInstrumented` already have between their bus-count read and their per-bus element reads. The durable fix is a copy-on-write snapshot of `returnBuses`/`sends` read by the render path, or routing structural edits through the story-314 `setGraph` epoch.
