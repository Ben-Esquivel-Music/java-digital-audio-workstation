# RT-Safe Error Channel and Callback Guards

## Motivation

The two default streaming backends handle a render-path exception in the two worst possible ways, and every guard that does exist is a black hole:

- **PortAudio — the production default (`AudioBackendFactory.createDefault()` wired at `MainController.java:802`) — is one exception from JVM death.** The FFM upcall body calls `callback.process(...)` with no try/catch (`PortAudioBackend.java:448`). The callback target is `AudioEngine::processBlock`, registered raw at `AudioEngine.java:442` and `:519`, and it **throws `IllegalStateException` when `running` is false** (`AudioEngine.java:910-913`) — `stop()` flips `running` independently of stream teardown, so a stop racing an in-flight callback throws straight through the FFM upcall into the native frame. Any plugin or DSP `RuntimeException` in the render pipeline takes the same exit. An exception crossing an FFM upcall boundary kills the JVM — total loss of an unsaved session. The codebase already knows better one module over: the ASIO upcall wraps its body in a catch-everything guard precisely because the driver cannot recover from a Java stack unwind (`AsioBufferSwitchShim.java:364-371`).
- **JavaSound — the always-available fallback — dies silently and lies about it.** The render loop calls `currentCallback.process(...)` bare inside `while (streamActive)` (`JavaSoundBackend.java:265-275`) on an unwrapped virtual thread (`:155`). One DSP exception kills the thread; `streamActive` stays true, so the backend *reports* an active stream while producing silence forever. Nothing notices, restarts, or reports it.
- **The existing swallows are amnesiac.** The ASIO shim swallows `Throwable` in its upcall and drain publisher with no counter, health flag, or user signal (`AsioBufferSwitchShim.java:364-371`, `:515`), and `AudioWorkerPool` swallows every task `Throwable` with an empty catch (`AudioWorkerPool.java:216`) — a track whose inserts throw every block silently mixes a stale buffer, uncounted.
- **The fan-out choke points have no isolation.** `FxDispatcher.pulse()` (`FxDispatcher.java:443-461`) runs each keyed runnable (`:455`) and each continuous-channel drain (`:460`) bare — one persistently throwing consumer propagates onto the FX thread and starves the playhead, status cells, and every other channel, sixty times a second. `DefaultEventBus` does isolate subscriber throwables but routes them only to the invisible log (`DefaultEventBus.java:191`, `:352`).

For a studio engineer this means a single misbehaving plugin can end the session — either the whole application vanishes mid-take (PortAudio) or audio stops with the UI still claiming an active stream (JavaSound) — and lesser failures (a failing track render, a throwing meter consumer) degrade the session with zero trace. The book's principle §2.3 governs the fix: the RT thread records, it never surfaces — atomics and rings on the callback path, a drain on the FX pulse turning records into visible facts.

## Goals

- **PortAudio upcall guard.** Wrap the entire FFM upcall body — including buffer marshalling — in a catch-everything guard mirroring `AsioBufferSwitchShim.java:364-371`: on `Throwable`, zero the output block, record into the health record (failure code + counter bump), and return the stream-continue status. An exception must never cross into the native frame.
- **Engine stop-race fix.** `processBlock` on a stopped engine renders silence and returns — the `IllegalStateException` at `AudioEngine.java:910-913` stops being an exception path. A stop racing a live callback is normal teardown, not a fault: it produces no failure record and no surface (book §5.1 row 4 — claiming a fault that isn't one is also lying).
- **JavaSound per-iteration guard with honest exit.** Each loop iteration guards the callback invocation: one bad block zeroes output, records, and continues. Past a consecutive-failure threshold the loop exits *honestly* — stream marked inactive, plus a channel-B record the drain escalates to an "audio engine fault — restart?" surface. The thread never again dies with `streamActive` still true.
- **Counters behind the existing swallows.** The ASIO shim's upcall/drain `Throwable` swallows and `AudioWorkerPool`'s task catch each bump a named counter in the health record. The swallow was always RT-correct; the defect was the missing count.
- **The RT health record and error ring** (channel B of book §3.2): a small struct of atomics — per-category failure counters, last failure code, and a callback heartbeat timestamp (shared substrate for story 338's watchdog) — plus a fixed-size ring of recent failure descriptors, preallocated at stream open. Nothing on the RT side touches a `SubmissionPublisher`, a lock, or the logger.
- **The FX-pulse drain and escalation.** A drain on the `FxDispatcher` pulse reads the health record once per frame and converts deltas into facts: first failure of a fingerprint → WARNING toast; sustained failure → "audio engine fault — N callback errors" with a restart-engine action. Rate limiting and escalation follow book §6.2 (frequency raises prominence, not volume).
- **Pulse isolation.** `pulse()` wraps each keyed runnable and each continuous-channel drain in its own guard: log once per offender fingerprint, keep draining the siblings, route repeated offenders to the story-336 funnel. One throwing meter consumer never again starves the playhead.
- **Bus escalation.** `DefaultEventBus`'s existing per-subscriber isolation gains the same fingerprint counting, so a persistently failing subscriber becomes a visible fact instead of an invisible WARNING.

## Goals — Tests

- **RT purity gate (book §6.3 gate 3).** Extend the bytecode-sentinel idiom of the ASIO shim tests (`RealTimeSafeContractTest`): the callback-path guard classes and the health record must not reference `SubmissionPublisher`, `ReentrantLock`, logging, or collection iteration in RT methods — asserted for the PortAudio and JavaSound paths, not just ASIO.
- **PortAudio guard test:** injecting a throwing callback yields a zeroed output block, a counter delta, and the stream-continue status returned from the upcall — no `Throwable` escapes toward the native boundary.
- **Stop-race test:** a `stop()` racing an in-flight `processBlock` renders silence with no exception and **no failure record** — the not-a-fault row is part of the contract.
- **JavaSound guard test:** a throwing callback produces silence-and-continue with a counter delta; sustained consecutive failures make the loop exit honestly — `streamActive` false plus an escalation record — never active-and-silent. A transient failure (below threshold) leaves the stream running.
- **Worker-pool counter test:** a task that throws every block bumps the named counter each time; the drain aggregates the deltas and escalates past the sustained threshold instead of toasting per occurrence.
- **Pulse isolation test:** a keyed runnable and a continuous-channel drain that throw every frame do not prevent sibling channels from draining in the same frame; the offender is logged once per fingerprint; a persistent offender escalates to a visible fact.
- **Bus escalation test:** a persistently throwing subscriber becomes a surfaced fact at the threshold while other subscribers keep receiving events.
- **Drain escalation test:** first failure of a fingerprint surfaces a WARNING immediately; repeats within the window are counted silently; a repeat after the window re-surfaces carrying the accumulated count; sustained failure produces the persistent fault fact with a restart action.

## Note from Story 336

- **JavaFX stops reporting a failing pulse after 100 throws.** `FxDispatcher.pulse()` is the `handle` body of the dispatcher's single `AnimationTimer` (`FxDispatcher.java:712-718`), which `start()` registers once per session. JavaFX's `AbstractPrimaryTimer` (javafx-graphics 27, `AbstractPrimaryTimer.java:372-391`) counts the throwables that leave a registered timer's `handle`. It passes the first 100 for that timer (`FAILING_TIMER_THRESHOLD`, `:68`) to the FX thread's uncaught-exception handler. It then logs one WARNING on the JavaFX logger ("Too many exceptions thrown by …, ignoring further exceptions.") and drops every later one silently.
- **Every throwing pulse counts toward that cap.** A keyed runnable (`FxDispatcher.java:635`) or a channel drain (`:640`) that throws leaves `pulse()` at once, and a participant's throw is held back and rethrown at the end of the pulse (`:642-644`). So after 100 such pulses in a session, a pulse failure no longer reaches the story-336 FX handler at all: no log record, no toast. The pulse's current locators are `FxDispatcher.java:618-645`; this story's `:443-461` predates story 318's participants.
- **This story's pulse isolation therefore catches inside `pulse()`**, per keyed runnable, per channel drain and per participant, and reports from there. It must not rely on the timer to deliver a throw to the FX handler.
- **Until that guard lands, a pulse storm's tail reads as if the failure stopped.** A pulse storm that hits JavaFX's 100-throw cap stops reaching the story-336 FX handler. The story-336 funnel then writes the storm's tail, a history entry ending "… the last time at …" and its log line, which reads as if the failure stopped, when it was only no longer delivered. Once this story's per-runnable pulse guard lands, the tail is accurate on every path.
- **This story moves the render path's existing log-once sites to its RT channel.** Story 336's "Known limits" names this story as their owner. Among the sites are `EngineStreamPump`'s render loop (`renderLoop`) at `EngineStreamPump.java:363`, `:383` and `:407`, `PluginInvocationSupervisor`'s SEVERE record of an `Error` a supervised plugin throws (`PluginInvocationSupervisor.java:504`), and `RenderPipeline#renderBlock`'s once-only return-bus-cap notice (`RenderPipeline.java:805-813`), which is allow-listed in `RealTimeSafeContractTest` (`RealTimeSafeContractTest.java:873`). Since story 336, each of them formats a record and writes it to disk under the file handler's lock at its first fault, which can cost one extra dropout. When that write is the session's first write to the log file to fail, the same thread also runs story 336's write-failure notice, once per session: `LogSink`'s error manager takes its monitor and prints one line to standard error, the sink takes its own monitor, and `FailureFunnel.onSinkWriteFailure` takes `armLock` and, while the toasts are armed, formats a WARNING and posts it through `Platform.runLater`, which enters JavaFX's `Toolkit.class` monitor; moving the sites moves that notice off the render thread with them. The allow-list is asserted exactly, so the change that moves the `RenderPipeline` notice also removes its entry.
- **A render-path swallow that future story 443 leaves to this story.** `VelvetNoiseReverbProcessor`'s late-segment catch (`VelvetNoiseReverbProcessor.java:286`) discards a segment's failure on the render path, like the swallows this story's Goal "Counters behind the existing swallows" counts. Future story 443 names it as a render-path site its own route cannot report from, so this story's RT channel is its route.

## Resolution

No failure on the render path or in an FFM upcall is silent any more, none can cross into a native frame, and the engine no longer claims to play while its render drive renders nothing. Every method an FFM upcall stub binds catches everything and answers its ABI's safe value. A render thread never logs, locks or publishes a failure: it records it into its own lane of the engine's audio health record, and a drain on the FX pulse turns the counts into notices through story 336's funnel — a WARNING at once, repeats counted, an ERROR with an action when a failure is sustained, and an immediate reaction when the render drive halts. A stopped engine renders silence and records nothing. A pulse item or bus subscriber that throws no longer stops its siblings, and becomes a visible fact when it keeps failing. Every Goals — Tests bullet is met by the tests named below.

**The PortAudio upcall guard.** Since story 316 the PortAudio upcall enters `CallbackBackendAdapter.deviceCallback`, a ring hand-off, through `PortAudioBackend.CallbackInvoker.invoke`; on Windows the stub binds `invokeNarrowLong`, which delegates to `invoke`. `invoke` bumps its device heartbeat (`deviceCallbackPeriods++`) and computes `hostFrames` and `frames` with conditional expressions before its `try`. Inside it, the output segment is reinterpreted once and the old body runs unchanged in a private `render`. On any `Throwable` it calls `silenceAfterFault` in a nested catch-all — one bulk `fill((byte) 0)` of the host's extent, reusing the reinterpreted segment, never `framesPerBuffer`-based — then bumps `callbackFaults` and keeps `lastCallbackFault`; it returns `PortAudioBindings.PA_CONTINUE` on every path (rulings E1–E3). `invokeNarrowLong` wraps its delegation in a catch-all that only returns `PA_CONTINUE`. The backend keeps the counters of closed streams in a `record InvokerCounters`, swapped in one volatile write at `createCallbackStub`, at close (`reportClampedOversizedPeriods`) and at a failed `openStream`, and reports them, with an always-present device heartbeat, through `threadCounters()`. The invoker stays without `@RealTimeSafe` (`reinterpret` allocates) and is walked by gate 3 anyway. Tests: `CallbackInvokerTest.aThrowingCallbackSilencesTheHostExtentCountsTheFaultAndContinues` (the Goals — Tests PortAudio bullet), `aThrowingCallbackOnAShortHostPeriodZeroesOnlyTheHostExtent`, `anErrorFromTheCallbackNeverReachesTheNativeFrame`, `theNarrowEntryPointContinuesWhenTheCallbackThrows`, `aFailingOutputReinterpretIsCountedEvenWhenTheSilencingReinterpretFailsToo` and `aHealthyCallbackBeatsTheDeviceHeartbeatAndCountsNoFault`; `PortAudioBackendTest.threadCountersWithNoStreamAreZeroWithADeviceHeartbeatOfZero` and `retiringTheLiveInvokerKeepsItsCounts`.

**The ASIO upcall and its drain.** `AsioBufferSwitchShim.bufferSwitchUpcall` now carries `@RealTimeSafe`, is package-private, and is listed in `RealTimeSafeContractTest.RT_CALLBACK_BRIDGES` next to `bufferSwitch` (ruling E16). It bumps `deviceCallbackPeriods` before its `try`; on a fault it calls `silenceOutputHalf(bufferIndex)` in a nested catch-all, which bulk-zeroes every bound output segment of that half, then bumps `upcallFaults` and keeps `lastUpcallFault` (ruling E15). Before story 337 its catch only returned, so the half kept the previous cycle's samples. `publishDrained`, on `asio-input-drain`, counts a lost block in `publishDrops` with `lastPublishFault`. `AsioBackend` keeps the shim counters of closed streams in a `private record ShimCounters`, swapped at open (`openWithInputWidth`), in `rollbackOpen` and in `close()`, and reports upcall faults as callback faults, publish drops as lost input blocks and an always-present device heartbeat. Tests: `AsioBufferSwitchShimTest.aThrowingBufferSwitchSilencesTheOutputHalfAndCounts`, `aHealthyUpcallBeatsTheDeviceHeartbeatAndCountsNoFault`, `aPublishFailureOnTheDrainIsCounted` and `anAsioBackendWithNoStreamReportsZeroCountsAndAHeartbeatOfZero`.

**Backend threads and the pulled counters.** A backend's own threads keep single-writer `volatile` counters with a `volatile Throwable` for the last fault, and the engine pulls them (ruling E4). daw-sdk's new `record BackendThreadCounters` (`NONE`, `plus`) is returned by `AudioBackend.threadCounters()` and `NativeAudioBackend.threadCounters()`, whose defaults are `NONE`. `CallbackBackendAdapter.threadCounters()` sums its delegate's counters and its own: its `native-input-drain` now catches every throwable per block, counts the lost block (`inputBlocksLost`) and continues. On Java Sound's `javax-sound-capture` thread a throw from `decode` or `publishInput` loses one counted block and the loop continues; a throw from `line.read`, or a `VirtualMachineError`, ends the loop with one `inputHalts` count, unless the stream is closing or the thread is interrupted, which is teardown (ruling E17). The device-notification upcalls (`AsioFormatChangeShim.asioMessageUpcall`, `WasapiFormatChangeShim.queryInterfaceUpcall` and `onPropertyValueChangedUpcall`, `CoreAudioFormatChangeShim.listenerUpcall`) call `backend.noteDeviceNotificationFault(t)` in a nested catch-all, which bumps an `AtomicLong` on `AsioBackend`, `WasapiBackend` and `CoreAudioBackend` (ruling E31). `AudioEngine` attaches the open backend's `threadCounters` to its health record when a stream opens and for a retained failed hop (`attachBackendCounters`), and folds them in `clearOpenStream()` (`detachBackendCounters`); the attach baselines the source, so a reopen never counts a backend's history twice. `MockAudioBackend.setThreadCounters` lets engine tests drive the ledger. Tests: `CallbackBackendAdapterTest.aPublishFailureOnTheNativeInputDrainIsCountedAndTheDrainContinues` and `threadCountersSumTheDelegateAndTheDrain`; `JavaxSoundBackendTest.aFailingPublishLosesOneBlockAndTheCaptureContinues`, `aThrowingReadEndsTheCaptureWithOneHalt` and `aCloseMidReadRecordsNothing`; one test each in `AsioFormatChangeShimTest`, `WasapiFormatChangeShimTest` and `CoreAudioFormatChangeShimTest`; `BackendThreadCountersTest`; `AudioEngineBackendCountersTest.theOpenBackendsCountersReachTheRecordLiveAndSurviveTheClose`, `reopeningTheSameBackendNeverCountsItsHistoryTwice` and `countsABackendReportedBeforeTheStreamOpenedAreItsHistoryNotNewFaults`.

**The stop race.** Both `AudioEngine.processBlock` overloads return `boolean` (ruling E6). On a stopped engine they write silence through the new `@RealTimeSafe private static renderStoppedSilence` — `[0, min(max(numFrames, 0), plane.length))` of every non-null output plane and all of the interleaved output — and return `false` before the tap snapshot, so no metering stamp is consumed and nothing is recorded. The render drive exits on that `false` with no record; a throw while the engine or the pump is no longer running is teardown and also exits quietly (ruling E7). `AudioEngineTest.shouldThrowWhenProcessingWhileNotRunning` is rewritten in place as `processingOnAStoppedEngineRendersSilenceAndRecordsNothing`, with `processingOnAStoppedEngineToleratesShortPlanesNullPlanesAndNegativeFrames` and `processingOnARunningEngineReportsTheBlockRendered` beside it, and `EngineStreamPumpTest.engineStoppingMidStreamExitsThePumpQuietly` now also asserts no record and no uncaught-handler record (the Goals — Tests stop-race bullet).

**The render drive's honest exit.** The Goals' "JavaSound loop" is today `EngineStreamPump.renderLoop`, the one render drive every push backend runs. Its thread is a `RenderThread` that carries a `LaneRole.RENDER_DRIVE` lane claimed from `engine.audioHealth()` when the pump is built; the lane is retired on a confirmed `stop()` or a start that never ran the thread. The drive catches `Throwable` throughout (ruling E9). A fault from `processBlock` while the engine runs — a `LinkageError`, an `AssertionError` or a smuggled checked throwable included — records `audio.render` with the current streak, sinks a block of silence and continues; one rendered block resets the streak. `haltThreshold(format)` consecutive faults (`max(8, ceil(sampleRate / bufferSize))`, one second of audio counted in frames) or a `VirtualMachineError` end the drive through `halt`: `running = false`, then one `audio.render.halted` record with the cause, the streak and the stream generation, so a reader that sees the record already reads the drive dead (ruling E60), touching no lock, stream state, transport or backend (rulings E8 and E10). `sink` and `awaitSinkCapacity` faults are recorded as `audio.sink` and `audio.pacing`, floor-paced, and never end the drive. The lane beats once per block after `sink` returns normally (ruling E5). The three log-once sites and their flags are gone (ruling E14); the pump's logger is left for its backstop handler, the stop warning, a failed subscription cancel and the capture stream's `onError`. `AudioEngine.isRenderDriveAlive()` is true only while the stream is `RUNNING` and its pump runs, and `startAudioOutputLocked` reaps a dead drive through the existing stop and reopens it, so Play is never wedged; when that stop cannot join the old pump, the start refuses with `AudioBackendException`, attributed to the requested endpoint like every other refusal of the start, instead of opening over the unclosed stream (ruling E61). Tests: `EngineStreamPumpTest.processBlockFaultRendersSilenceAndLaterBlocksStillReachSink`, `sustainedRenderFaultsHaltTheDriveWithATerminalRecord`, `aTransientRenderFaultBelowTheThresholdLeavesTheDriveRunning`, `aVirtualMachineErrorFromProcessBlockHaltsAtOnce`, `aSmuggledCheckedThrowableIsARenderFaultNotADeath`, `theRenderDriveBeatsOncePerBlockTheBackendAccepted`, `theHaltThresholdIsOneSecondOfBlocksWithAFloorOfEight` and `stoppingThePumpRetiresItsLaneAndKeepsItsCounts` (the Goals — Tests JavaSound bullet), and `aThrowAfterTheEngineStoppedMidBlockExitsQuietlyWithNoRecord`; `AudioEngineRenderDriveHaltTest.aHaltedRenderDriveIsReportedDeadAndReapedByTheNextStart` and `onlyARunningStreamWithARunningPumpIsALiveRenderDrive`; `AudioEngineOutputTest.aStartOverAStreamWhoseStopTimedOutIsRefusedUntilTheOldPumpExits`. The four persistent sink and pacing tests stay as written.

**The health record.** daw-core's new package `core.audio.health` is exported only `to daw.app`, daw-core's first qualified export. `AudioEngine` holds one `AudioHealthRecord` for its whole life (`audioHealth()`, never null, never replaced, never reset; ruling E18). The record holds one `AudioHealthLane` per render thread, published as an immutable `LaneSet` by one volatile write, and a `BackendLedger` for the backend counters. A lane has one writer: `record` bumps an `AtomicLongArray` slot with a load and `lazySet`, keeps a per-category last failure in an `AtomicReferenceArray`, and samples a descriptor into a 16-slot ring that drops the newest when full and counts it lost (rulings E19, E21, E22). The drain copies a slot, nulls its references and only then advances. Retiring a lane folds its counts, beats, lost descriptors and last failures into the record and clears its slots, so totals only grow. Real-time sites record with `AudioFailureCodes` int constants (13 categories); the drain side reads `AudioFailureCategory` (slugs `audio.callback` to `audio.device`, ruling E23). `RenderThread` is a daemon platform thread at `MAX_PRIORITY` that carries its lane; `RenderThread.recordOnCurrentThread` and the record's own `recordOnCurrentThread` record only on a render thread and answer `false` elsewhere (ruling E20). The record is per engine and the lanes are allocated per render-pump start (a stream open or a resume) and per engine start that builds a worker pool, which is how "preallocated at stream open" is met. `AudioEngineLifecycleLockContractTest` allows the record's type under the lifecycle lock, and the lock's Javadoc gives the reason. Tests: `AudioHealthLaneTest` (7), `AudioHealthRecordTest` (15), `AudioHealthLanePublicationOrderTest` (1), which races a writer against the drain, and `RealTimeSafeContractTest.theHealthLaneAndTheHaltKeepTheInstructionOrdersTheirPublicationRestsOn`, which pins the lane's publication and release orders and the halt's order in the bytecode (rulings E21 and E60).

**The render-path sites.** On a render thread none of them logs or throws: each records into that thread's lane, except the supervisor, whose faults travel story 340's channel:
- **Worker pool.** `AudioWorkerPool(int size, AudioHealthRecord health)` builds its workers as `RenderThread`s with `WORKER` lanes. The inline path and `runTasks` record `audio.worker` with the task index, and `remaining.decrementAndGet()` sits in a `finally` (ruling E27); `close()` retires the lanes of the workers that joined. Tests: `AudioWorkerPoolTest.aTaskThatThrowsEveryBatchBumpsTheWorkerCounterEveryBatch` (the Goals — Tests worker bullet), `taskExceptionsAreSwallowedAndDoNotStarveFollowingBatches`, `theInlinePoolCountsOnTheCoordinatorsLane`, `aTaskFailureOffARenderThreadIsStillIsolatedButNotRecorded`, `aFailingTaskStillReleasesTheBatch` and `closingThePoolRetiresWorkerLanesAndKeepsTheirCounts`.
- **Automation binder.** In `ReflectiveParameterBinder.applyBindings` a setter that throws on a render thread records `audio.automation` (the binding's `PluginParameterTarget` as subject, its parameter id as detail) and then sets that binding's `disabled` flag; only `rebind` clears it, by replacing the binding objects (ruling E28). On a thread with no lane — an offline export, bounce or freeze — the binder still throws today's `IllegalStateException("automation setter for parameter " + b.target + " failed", t)` and disables nothing, so that render fails visibly (ruling E57). Tests: `ReflectiveParameterBinderTest.aThrowingSetterOnARenderThreadIsRecordedAndDisablesOnlyThatBinding`, `rebindReenablesADisabledBinding` and `offARenderThreadTheSetterFailureStillThrowsAndDisablesNothing`.
- **MIDI.** `MidiTrackRenderer` takes the record by constructor; its five render-path catches (`allNotesOff`, the two in `sendEventsAtFrame`, now an instance method, `renderSubChunk` and `renderSilence`) record `audio.midi` instead of logging or swallowing (ruling E30). Tests: `AudioEngineMidiPlaybackTest.aFailingSynthesizerIsRecordedOnTheRenderThreadAndNeverLogged` and `aFailingSynthesizerOffARenderThreadRecordsNothingAndLogsNothing`.
- **CLAP.** `ClapPluginHost.process` records a caught throwable, or the plugin's `CLAP_PROCESS_ERROR` report as the preallocated stackless `PROCESS_ERROR_REPORTED`, as `audio.plugin` and passes the input through; `ClapInsertEffect.process` records instead of its SEVERE log. Tests: `ClapInsertEffectTest.aCrashOnARenderThreadIsRecordedWithThePluginAsSubjectAndNeverLogged` and `ClapPluginHostTest.everyGuardedHostCallbackAnswersItsAbiValueOnAFaultAndRecordsIt`.
- **Velvet reverb.** `VelvetNoiseReverbProcessor.processLateSegments` restores the interrupt flag on `InterruptedException` and records nothing; on `ExecutionException` or `CancellationException` it zeroes that segment's work buffer and records `audio.dsp` with the segment index (ruling E29). - **E1** — The PortAudio guard lives in `CallbackInvoker.invoke`: heartbeat and pure arithmetic before a `try`, the old body moved unchanged into a private render method inside `try { … } catch (Throwable)`; on a fault it silences, records and returns `PA_CONTINUE`; `invokeNarrowLong` keeps delegating inside a catch-all whose only job is to return `PA_CONTINUE`; no `MethodHandles.catchException` combinator, no duplicated guard.

- **E3** — Every PortAudio fault returns `PA_CONTINUE`, never `paAbort` or `paComplete`; stopping is a decision for the watchdog or the honest exit, never for a single block.
- **E4** — Counters on backend-owned threads are pulled: a single-writer `volatile long` beside a `volatile Throwable` per writer, accumulated by each backend across its opens and exposed through one new `AudioBackend` default method returning an immutable SDK value ("no own threads, zero counts" by default), folded into the engine's record when a stream closes; no push sink, no record type in daw-sdk, no `AudioStreamCallback` hook.

**Known limits.**
- A PortAudio host that returns from `Pa_CloseStream` while a callback still runs jumps into a freed stub: native, not guardable from Java.
- A `native-input-drain` or `javax-sound-capture` thread that outlives a timed-out join can briefly double-write its counter: at worst a lost increment, never a torn value.
- A channel consumer that is a JavaFX method reference and throws inside JavaFX has `FxDispatcher`'s drain as its first host frame, so two such consumers throwing the same exception class share one fingerprint; the log record's offender names each.
- One fingerprint per streaming category: two plugins failing in the same category share one notice; its log record lists every distinct sampled anchor, up to 16.
- A thread with no lane — an offline export, bounce or freeze — records nothing. The MIDI renderer (no offline caller passes one: `OfflineStemRenderer` hands `renderOffline` a `null` renderer) and the return-bus notice stay silent there until story 443's route; the automation binder keeps its visible throw (ruling E57). Preventing the return-bus overflow is future story 452.
- A worker that does not join, or an orphaned pump, keeps a live lane for the engine's life.
- `exports com.benesquivelmusic.daw.core.audio.health to daw.app` is daw-core's first qualified export; `AudioEngine.audioHealth()` returns a type that other modules cannot see.
- A one-shot record written between the drain's sample poll and its totals read is counted in one frame and sampled in the next, so its count joins that frame's last sampled subject or `unknown`. The same skew can count one input halt twice across two frames.
- A bus sink that rethrew one shared exception instance on every failure would grow that instance's suppressed list; the production sink never throws.
- `AsioBackend`'s fold of shim counters across opens has no unit test, because an open needs a native driver; PortAudio's same fold is tested.
- When the restart's record guard ends a take and that Stop closes the stream, the restart reopens nothing, so the engine-fault fact stays latched until a later Play's render drive beats for one fault-free second, or until a second Restart Audio Engine, which begins with no stream open and so succeeds when it returns normally (ruling E62).
- The `finally` around `AudioWorkerPool.runTasks`'s `remaining.decrementAndGet()` (ruling E27) is untested: its handler, the lane record, cannot throw — the health gate holds it to zero findings — so no test can tell the `finally` from a decrement after the catch.
- A CLAP host-callback fault (`pendingEventsSize`, `pendingEventsGet`, `ostreamWrite`, `istreamRead`) records no subject, because the callbacks are static, so its notice uses the unnamed plugin sentence (ruling E64); naming the plugin is future story 451's.
- If `asio-input-drain` outlives the shim close's bounded join, a block it loses after that join is counted nowhere.
- A halt close can fall due while a reopen on another thread — Restart Audio Engine, Settings ▸ Apply or the format-change reopen — holds the engine's lifecycle lock, on the halt's own frame or on any later frame's retry: the drain then waits on the FX thread until the open ends and closes the reopened stream, so the restart reads as failed (ruling E62) or leaves no stream open, and Play reopens it. Scoping the close to the halted stream's generation without waiting on the lock is future story 453's.

- The record is per engine and only the lanes are allocated, the render drive's per render-pump start (a stream open or a resume) and the workers' per engine start that builds a worker pool (rulings E18 and E59); the heartbeat is two counters, not a timestamp (ruling E5).
