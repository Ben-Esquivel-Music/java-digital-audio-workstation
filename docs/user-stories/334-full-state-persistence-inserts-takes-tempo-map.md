# Full-State Persistence: Plugin Inserts, Take Stacks, Tempo Map

## Motivation

Whole categories of a session either cannot be expressed by the project format or are silently discarded on load:

- **Plugin-backed inserts are silently dropped, shifting the chain.** `InsertEffectFactory.createSlotFromPlugin` (`InsertEffectFactory.java:86` (stale)) infers a *built-in* type (`InsertEffectFactory.java:107` (stale)) — null for any external-JAR or CLAP plugin. The serializer guards the `effect-type` attribute *and all parameter children* behind a non-null type (`ProjectSerializer.java:510-512` (stale)), so a plugin slot is written as name/bypassed/expensive only. On load, `parseInsertSlot` returns for an empty `effect-type` and **explicitly returns for `CLAP_PLUGIN`** (`ProjectDeserializer.java:893-902` (stale)) — the slot is never recreated and every later slot shifts one position up. A mix using any third-party insert reopens with a different, shorter chain and no warning.
- **A built-in insert of an unknown type is dropped the same way.** `ProjectDeserializer.createInsertSlot` resolves `effect-type` with `InsertEffectType.valueOf`, and the whole of `parseInsertSlot` sits in `catch (IllegalArgumentException ignored) { // skip unknown effect types }`, so an insert whose type this build does not know disappears on open with no WARNING, no report and no degraded-open backup while every later slot moves up one position. An analyzer insert whose `analyzer-plugin-id` this build does not know is dropped the same way: `AnalyzerInsertPersistence.read` returns `null` for it, and `parseInsertSlot` returns without adding a slot. A legacy id-keyed `<parameter>` whose value the effect's setter rejects is not caught there at all, because the reflective parameter handler (`ReflectiveParameterRegistry.createParameterHandler`) rethrows the setter's `IllegalArgumentException` as an `IllegalStateException`, which escapes the open; and a named `<parameter name="…">` out of its declared range is clamped by `ReflectivePresetSerializer.restore` with no word.
- **The installed-plugin registry is session-scoped.** `PluginRegistry` keeps entries in in-memory collections only (`PluginRegistry.java:25-27` (stale), registration at `:37` (stale)); nothing persists them and nothing re-registers at startup — which turns the dropped-insert bug above from "recoverable by hand" into "unrecoverable without re-installing first". Story 303 landed its install flow with a truthful no-persistence notice for exactly this gap.
- **Take stacks and comping are never persisted.** Tracks own `TakeComping` with its take lanes and comp regions (`Track.java:98-99` (stale)); loop recording populates them (`RecordingPipeline.java:294` (stale)) and the comp tool consumes them in production — yet the serializer emits no take-lane or comp-region element of any kind (the only `take` token in the format is the `takes-folded` fold-state attribute, `ProjectSerializer.java:292` (stale)). Every take but the composited result is lost on save.
- **The tempo map cannot be expressed.** `Transport` is backed by a full `TempoMap` (`Transport.java:74` (stale)) that the timeline ruler already consults (`TimelineRulerModel.java:58`), but the format serializes exactly one beat-0 tempo and time signature (`ProjectSerializer.java:235` onward (stale)). Tempo or meter changes are unrepresentable end to end.

For a studio engineer: the mix topology changes silently between sessions, comped performances collapse to a single take, and a song with a tempo change cannot be saved at all. Mix topology is data, not a cache — it must never load shorter than it saved.

## Goals

- **Plugin-slot descriptor** (design book §4.5): a plugin-backed `InsertSlot` serializes plugin identity (stable manifest id + version — never a jar path), source kind (external JAR / CLAP), display name, bypass/expensive flags, chain position, and the plugin's opaque state (the reflective parameter snapshot where that path applies, otherwise the plugin's own state blob).
- **Unresolved placeholder, chain order inviolate**: on load the descriptor resolves through the plugin registry; resolution failure produces a placeholder slot in the same chain position — audibly bypassed, visually distinct in the rack (Plugin View book idiom), carrying the full descriptor so a later install or relink restores it losslessly. The chain never shifts and a slot is never silently deleted.
- **An unknown built-in type or analyzer keeps its place, and the open says so**: an `<insert effect-type="NOT_A_TYPE" name="Old FX">` between two built-in inserts reopens as a §4.5 placeholder in the same position, labelled from `insert@name`, audibly bypassed and written back unchanged; the neighbouring slots keep their positions and sidechain keys (`sidechain-source`). An `<insert analyzer-plugin-id="…">` naming an analyzer this build does not know also keeps its place as a placeholder, labelled from `insert@name`, shown in the rack and written back unchanged. Each placeholder logs one WARNING naming its strip, its chain position and the saved `effect-type` or `analyzer-plugin-id` (quoted through story 330's `UnreadProjectItem.logText`), and arms no backup, because it is written back unchanged. A built-in-type placeholder is counted in the open's report in one clause with this story's other placeholders (for example `1 insert not available (bypassed, kept as saved)`, worded by the studio engineer in story 330's form). An analyzer placeholder is not counted in that clause: an analyzer is view-only (a transparent insert whose output is its input), so it changes nothing the engineer hears and is logged only (story 330's studio ruling D1, analyzer state is a meter view preference).
- **A rejected parameter is skipped and reported**: a parameter whose value the effect rejects skips that parameter, not the slot. It logs one WARNING naming the insert, the parameter's id and its saved value, is counted in the open's report, and arms the degraded-open backup (story 330's studio ruling Q1: its raw value is lost on save). Reporting the named parameters `ReflectivePresetSerializer.restore` clamps silently is this story's too, as a clamp under story 367's rule (a WARNING with the saved and the applied value, counted, backup armed), because this story owns how insert parameters are restored and 367 covers the mixer's own values.
- **Installed-plugin registry persists**: registry entries plus manifest provenance from the story-303 install flow persist in the app configuration directory (written via the story-331 atomic-replace writer) and re-register at startup. Story 303's truthful no-persistence notice comes out when the gap closes.
- **Take schema** (book §4.6): per-track take lanes and comp regions serialize alongside clips, comp regions referencing take lanes by id, so the comping surface reopens exactly as left; the schema stores the ordered segment-file list that Book 2's story 323 finalises.
- **Tempo-map schema**: the tempo map serializes its full tempo-change and meter-change lists (position, value, transition type), with the single beat-0 attributes retained as the backward-compatible degenerate case.
- **Migration + parity**: every format addition rides the story-188 migration registry (schema-version bump, pre-migration backup; old files open unchanged with defaults), and extends the story-330 write/read parity harness **in the same PRs** — the §3.1 inventory rows for plugin inserts, takes, tempo map, and the registry flip to OK.

## Goals — Tests

- **Mixed-chain round-trip**: a chain of built-in + external-JAR + CLAP inserts saves and reopens identical in content **and order**, parameters included where the snapshot path applies.
- **Placeholder round-trip**: uninstall one plugin → reopen → a placeholder holds its exact chain position, audibly bypassed and visually distinct; reinstall → the slot restores losslessly from the preserved descriptor. No load path ever shortens a chain silently.
- **Unknown built-in type or analyzer**: a chain of two built-in inserts with `<insert effect-type="NOT_A_TYPE" name="Old FX">` between them reopens with three slots — the placeholder in the middle, labelled `Old FX`, audibly bypassed, and written back unchanged by the next save — and both neighbours keep their positions and sidechain keys. The open logs one WARNING naming the strip, insert 2 and `NOT_A_TYPE`, the announcement counts one placeholder, `losesSavedContent()` is false, and the first save writes no `.bak`. An `<insert analyzer-plugin-id="com.example.gone" name="Old meter">` in the middle keeps its place the same way, labelled `Old meter`, shown in the rack and written back unchanged, with one WARNING naming the strip, insert 2 and `com.example.gone`, no announcement clause, `losesSavedContent()` false and no `.bak` on the first save.
- **Rejected parameter**: a built-in insert holding one legacy `<parameter id="…" value="…"/>` that its setter rejects reopens with that parameter at its default and every other parameter restored; the open logs one WARNING with the parameter's id and saved value and counts it, `losesSavedContent()` is true, and the first save writes one `project.daw.degraded.*.bak` byte-equal to the fixture. A named `<parameter name="…">` saved out of its declared range opens clamped, logged with the saved and the applied value, and counted; `losesSavedContent()` is true and the first save writes one `project.daw.degraded.*.bak`.
- **Registry persistence**: install a third-party plugin → restart the app → the registry is intact and the plugin usable with no re-install; the story-303 no-persistence notice is gone.
- **Take round-trip**: loop-record a take stack (Book 2's capture stories landed), make comp selections, save, close, reopen → take lanes and comp regions (the comp selections) are identical and the comping surface resumes where it left off.
- **Tempo-map round-trip**: mid-song tempo and meter changes survive save→reopen, and the timeline ruler renders the same grid before and after (it reads the same `TempoMap`).
- **Parity-harness extension**: each new element/attribute registers in the story-330 harness; removing any new element's reader turns the harness red with the offending name.
- **Migration test**: a pre-334 project file opens unchanged through the story-188 registry (version bump honoured, absent elements defaulted, pre-migration backup written).

## Resolution

Saving now keeps every insert of a chain in its place — first-party plugins, external JAR plugins and CLAP plugins through one descriptor — together with each track's take lanes and comp regions and the transport's tempo and meter changes, and the installed third-party plugins survive a restart. The project format is schema version 3. An insert the open cannot load keeps its place offline: it passes audio through unchanged, every surface that shows inserts says so and why, and the next save writes it back as saved. Every bullet of the Goals — Tests is met as follows.

**Plugin-slot descriptor.** The writer is `ProjectSerializer.buildMixerChannelElement`: every slot that holds a plugin, an analyzer aside (it keeps its `analyzer-plugin-id`), goes through `writePluginDescriptor`, which writes `plugin-source` (`built-in`, `jar` or `clap`; `PluginSourceKind`), `plugin-id` and `plugin-version` — never a path — and then the plugin's state: a CLAP plugin's state as Base64 `<plugin-state>` text, asked of the plugin during the capture on the thread that owns the model (`writePluginState`); the named values when the processor declares `@ProcessorParam` accessors (`writeNamedParameters`); otherwise every value of the slot's id-keyed parameter store. A built-in DSP slot with no plugin keeps its `effect-type`. The reader is `ProjectDeserializer.parseInsertSlot`, which reads every name this build writes on an `<insert>` by name before it branches. A first-party descriptor resolves by descriptor id among this build's own providers (`BuiltInDawPlugin.createById` over the lazily built `BuiltInPluginIndex`); a JAR or CLAP descriptor resolves through the `PluginResolver` the open was given (`ProjectManager.setPluginResolver`; in production the `PluginRegistry`). No class named in a file is ever loaded. Id-keyed plugin parameters reach the plugin on the parse worker before the slot is published (`InsertSlot.applyParameterNow`). A processor's `@ProcessorParam` setters are bound through the public lookup (`ReflectiveParameterRegistry.createAudioParameterSetter`), which needs no read of the plugin's module: in the application's own launch daw.core is a named module that does not read the unnamed module of a JAR plugin's class loader (`PluginSetterBindsWithoutModuleReadsTest`, which runs the binding in a JVM of its own). A plugin installed in another version than the saved one loads with the saved state and logs one INFO line naming both versions. `MixedInsertChainPersistenceTest.aChainOfBuiltInJarAndClapInsertsReopensIdenticalInContentAndOrder` meets the "Mixed-chain round-trip": a chain of a built-in effect, JAR plugins resolved through a real `PluginRegistry`, a CLAP host (`FakeClapHost`, whose output follows its state bytes, through a resolver standing in for story 034's) and a first-party plugin reopens with the same kinds, ids, versions, names, flags, parameters and state in the same order, and each strip renders bit-equal to its render before the save from the first sample. `PluginInsertDescriptorPersistenceTest` covers the rest (`firstPartyPluginsReopenAsThePluginInOrder`, `aStoreParameterReachesThePluginBeforeItsFirstBlockAndARefusedOneIsReported`, `aPluginSavedWithAnotherVersionOpensTheInstalledOneWithOneInfoLine`, the CLAP state cases and `everyCauseLogsItsExactLine`), and `PluginSourceKindTest` and `PluginResolutionTest` the identity types.

**Offline inserts (§4.5 placeholder).** An insert the open cannot load becomes `InsertSlot.ofOffline` (`ProjectDeserializer.addOfflineInsert`): a `PassThroughProcessor`, whose output equals its input at zero latency whatever the stored bypass, that holds no plugin (so it is never an instrument and has no sidechain input) and carries an `OfflineInsert` — the `OfflineCause` and the element as saved (`SavedInsert`). The causes are the sealed `OfflineCause`: an effect type this build does not have or cannot run in the project's format, a first-party plugin it does not have, an external plugin not installed, installed as the other kind or missing at startup, a saved state the plugin refused or that is not valid Base64, a plugin that failed to load, a snapshot restore that loads no installed plugin, a stub that records no identity, and an unknown analyzer. The writer, `ProjectSerializer.writeOfflineInsert`, writes the saved attributes and the `<parameter>` and `<plugin-state>` children back as read; only the bypass a user action set (a mixer-snapshot recall) and a sidechain key that resolved at open, written from the live strip, come from the session. Remove and move are ordinary undoable edits. Every insert surface marks the slot with the word `Offline`, in the warn role: the rack row (`InsertEffectRack`: style class `insert-slot-offline`, a `DawIcon.WARNING` mark in place of the bypass toggle, the name muted, the tooltip `<name> is offline: <reason>. It passes audio through unchanged and is kept as saved.<action>`, a context menu holding only Remove, no editor and no sidechain selector), the mixer strip's dot (`InsertSlotModel.offline`, never active), the track header's badge (`<name> (offline)`) and the Inspector row (`insert-dot-offline`, the word, no ✎); `PluginViewController.openSlotEditor` opens nothing for an offline slot. Every text is in `Messages.properties`, read through `OfflineInsertText`. The "Unknown built-in type or analyzer" binding tests are `OfflineInsertPersistenceTest.anUnknownBuiltInTypeKeepsItsPlaceBetweenTwoBuiltInsAndIsWrittenBackUnchanged` and `anUnknownAnalyzerKeepsItsPlaceIsLoggedOnlyAndIsWrittenBackUnchanged`. The "Placeholder round-trip" is `OfflinePluginInsertReopenTest`: `anUninstalledPluginOpensOfflineInPlaceAndAReinstallRestoresItLosslessly` (the uninstalled plugin offline at index 1, the strip rendering bit-equal to the same strip without that slot; an install while the project is open changes nothing; a reopen, with or without a save first, restores the plugin and renders bit-equal to the strip before the uninstall) and `noReadingDoorShortensTheChain` (plain open, archive restore, journal replay and interrupted-save promotion; the snapshot door is `SnapshotRestoreOfPluginInsertsTest.anUninstalledPluginRestoresOfflineAsNotInstalledAndTheChainKeepsItsLength`). `OfflineInsertAudioTest`, `OfflineInsertEditsTest`, the rest of `OfflineInsertPersistenceTest` (including `aBypassDecisionARecallSetsIsWrittenBack`) and, in daw-app, `OfflineInsertSurfacesTest` and `OfflineInsertStyleTest` cover the rest.

**Insert reader honesty.** No load path shortens a chain or fails an open because of an insert. A ninth or later insert is skipped and reported, and the open succeeds. Named parameters are restored through `ReflectivePresetSerializer.restoreEach`, which reports each value as applied, clamped, rejected, unknown or not finite (`ParameterRestore`); built-in id-keyed values go through the effect's handler, a refusal counting as rejected; plugin store values are clamped to the store's range and applied with `applyParameterNow`. Every value the open could not apply as saved is an `INSERT_PARAMETER_ADJUSTED` item with its exact line, and a working insert's `sidechain-source` that names no strip is a removed mixer assignment. Whatever a plugin's own code throws while its insert opens — in the resolver, while its descriptor is read, its slot made or `activate()` run, while it takes its parameters, or when it is asked for its latency — disposes what was built first. Then anything but the virtual machine's own error opens the insert offline as failed to load, a `StackOverflowError` and a checked exception the code does not declare included (`PluginResolution.FailedToLoad.rethrowIfFatal`); the virtual machine's own error — any other `VirtualMachineError` — fails the open. The latency query is the load's last step: the slot's processor is asked once, after `activate()`, the CLAP state and the saved parameters, and a query that throws names the call in the detail, `JAR plugin 'com.example.comp' version '1.2.0' failed to load (NullPointerException when asked for its latency)`: a plugin that cannot state its latency cannot be compensated, so its insert is a pass-through at zero latency like every offline insert (ruling 4 Q8). A plugin that answers that one query and throws at a later delay-compensation pass of the same open still fails the open; future story 432 owns that case. A CLAP plugin that throws on its saved state has refused it, and opens offline too; a plugin whose `dispose()` throws is logged at FINE. A read that fails after building inserts releases them (`ProjectDeserializer.disposeUnopened`), whatever the failure, and a channel's retirement disposes every slot whatever one slot's plugin throws as it is disposed. The "Rejected parameter" binding tests are `InsertParameterRestoreTest.aRejectedLegacyParameterIsSkippedReportedAndBackedUp` and `aNamedParameterOutOfRangeOpensClampedReportedAndBackedUp`, with `everyParameterProblemLogsItsExactLine`; `OfflineInsertPersistenceTest.aNinthInsertIsSkippedReportedAndTheOpenSucceeds` and `anUnresolvableSidechainOnAWorkingInsertIsAReportedRemovedAssignment`, `PluginInsertDescriptorPersistenceTest.aPluginThatThrowsAnErrorWhileItsInsertOpensIsDisposedAndOpensOffline`, `aStackOverflowInThePluginsOwnCodeIsThePluginFailingToLoad`, `aVirtualMachineErrorFailsTheReadAfterTheOpeningPluginIsDisposed`, `aPluginWhoseInitializeThrowsAnUndeclaredCheckedExceptionOpensOfflineAndIsReleased` and `aReadThatFailsAfterBuildingInsertsReleasesTheirPlugins`, `PluginLatencyQueryPersistenceTest`, `MixerRetiredChannelLifetimeTest.aPluginWhoseDisposeThrowsLeavesNoOtherInsertUndisposed`, `ReflectivePresetSerializerTest.restoreEachReportsClampsRejectionsAndUnknownNames` and `AnalyzerInsertPersistenceTest` cover the rest.

**Installed-plugin registry.** The list persists in `~/.daw/plugin-registry.json` (`InstalledPluginStore`, schema `"1"`, written only through the `AtomicFileWriter` on `daw-plugin-registry-write` virtual threads), and each installed JAR is copied under `~/.daw/plugins/<id>/<version>/` (`PluginRegistry.stageJar`; a rebuild of an installed version goes to `<version>~<n>`). `MainController.initialize` builds the store and the `PluginRegistry` over it, starts `PluginRegistry.restore()`, registers the store's pending writes with `ProjectManager.alsoAwaitBeforeExit` and makes the registry the open's resolver. The restore runs on a `daw-plugin-registry-restore` virtual thread: it lists every readable entry as pending before any third-party code runs, then checks each and publishes it loaded or Missing with its reason — never dropped; a plugin whose code throws while it is checked, a `StackOverflowError` included, fails that entry alone, and the check never asks a plugin for its latency. A list or entry this build cannot read is copied once when read — or, when the copy fails, the list is left as it is and every later save makes the copy first (`InstalledPluginStore.Listing.copy`, `RestoreReport.listCopyOwed`). A JAR copy no entry holds is deleted at the first startup that reads the list with no problem and finds no kept copy of it: while any copy of the list is kept beside it (a `plugin-registry.json.*.bak`, in any case), the startup sweep deletes nothing under the plugins folder and logs one INFO line naming the first copy, and a folder that cannot be searched for copies counts as holding one (`InstalledPluginStore.sweepUnreferenced`; ruling 4 Q7). One startup notification, with a `Manage Plugins…` action, says what the restore found (`MainController.missingPluginsMessage`), and a failed write is notified once per session. Install (`PluginInstallPanel`) refuses a manifest whose id or version disagrees with the plugin's descriptor and a bundle that declares one id for two classes, and a row of an installed id says `Replaces <name> <version>`. `PluginRegistry.resolve` waits for the restore, at most 60 s (once a wait has run out, no later open waits), and gives each insert a fresh instance with a class loader of its own; after a wait that ran out, a JAR plugin not yet loaded opens as failed to load (`TimeoutException`). The snapshot restore reads on the FX thread and asks `PluginRegistry.withoutLoading()`, which never waits and never constructs. Story 303's notice and its `.plugin-manager-notice` rule are gone, the Manage Plugins header reads `Installed Plugins:`, a Missing row ends `— Missing: <reason>`, and both the Manage Plugins list and an open plugin browser read the installed plugins again when the restore completes, holding the dialog or browser only weakly, so one closed while the restore runs is not kept for as long as it runs. The "Registry persistence" binding tests are `PluginRegistryRestartTest.anInstalledPluginIsIntactAndUsableAfterARestart` (a new registry over the same folder restores the entry, and a project with that insert opens with no unread item and renders bit-equal to the plugin before the restart) and `PluginManagerShowsNoSessionNoticeTest.theNoPersistenceNoticeAndItsStyleAreGone`; the rest of `PluginRegistryRestartTest` (Missing entries, the open waiting for the registry, the restore wait, the startup sweep and the kept copy that holds it, a plugin that throws or overflows its stack while checked, a plugin whose latency query throws), `PluginRegistryIdentityTest`, `PluginRegistryTest`, `InstalledPluginStoreTest`, `ExternalPluginLoaderTest` and `ExitWaitsForTheWritesTest` in daw-core and `MissingPluginRowTest`, `ManifestIdentityInstallTest`, `MainControllerMissingPluginsNoticeTest` and `SourcePinnedWiringTest.theInstalledPluginRegistryPersistsIsAwaitedAtExitResolvesOpensAndIsAnnouncedOnce` in daw-app cover the rest.

**Take lanes and comp selections.** The writer, `ProjectSerializer.buildTrackElement`, marks a main-lane clip that is comp output with `comp-output="true"` (`TakeComping.savesAsCompOutput`), and `buildTakes` writes `<takes>` right after `<clips>`: one `<take id name muted>` per lane with its clips through the shared clip writer, then one `<comp-region take-id start-beat duration-beats>` per region, read only through `TakeComping.takeLanesAsSaved`, `compRegionsAsSaved` and `clipsOf`. A lane's solo (an audition), the swipe and the active tool are not saved. The reader, `ProjectDeserializer.parseTakes`, restores each lane under its saved id (`TakeLane(UUID, String)`; a missing, malformed or repeated id gets a fresh one with a WARNING), reads lane clips through the shared clip reader, whose lines name the take, and resolves regions by the id as saved; an unusable region is skipped, counted and backed up. `adoptSavedCompOutput` then adopts the marked clips as the comp's current output (`TakeComping.adoptCompOutput`): the open never compiles, so hand edits on the comp output survive the reopen and the next swipe replaces exactly those clips. Every lane's audio is session content: the archive packages it (`ProjectArchiver` through `TakeComping.referenceHoldersAsSaved`), the missing-assets report counts it and the relink reaches it (through `ProjectAssetReferences.everyClipOf`), and rehydration decodes it after the sources the main lane plays (`ClipRehydrator.scheduledSources`). The "Take round-trip" binding test is `LoopRecordedTakeStackReopenTest.aLoopRecordedTakeStackWithCompSelectionsReopensIdentical`: a real loop record of a stereo input (440 Hz left, 660 Hz right), comp selections across two lanes, save and reopen give equal lanes (order, id, name, mute, clips and segments), regions and comp output, with no lane soloed; each lane clip holds the captured channel count and samples; a swipe after the reopen replaces exactly the adopted output, plays no beat twice and slices the selected lane at the region's offset. Its undo is ruled by ruling 3 Q1 (below). `editedCompOutputSurvivesReopenAndIsAdoptedNotRecompiled`, `aLaneSoloedAtSaveReopensUnsoloedWithTheSelectionCompile`, `TakeStackPersistenceTest`, `TakeLaneAssetsTest`, `ClipRehydratorTest.mainLaneSourcesDecodeBeforeSourcesOnlyTakeLanesHold`, `TakeCompingSavedCompTest` and, in daw-app, `RestoredTakeLanesCanvasTest.restoredLanesAndRegionOverlaysAreLaidOutAndDrawn` cover the rest. The comping surface resumes at the model; making the COMP tool selectable is stories 345 and 328's (their notes).

**Tempo map.** The writer, `ProjectSerializer.buildTempoMap` (from `buildTransport`), writes `<tempo-change position bpm transition>` and then `<meter-change position numerator denominator>` for every change after beat 0; beat 0 stays in the `tempo` and `time-sig-*` attributes, one authority per fact. The reader, `ProjectDeserializer.parseTransport`, takes exactly what the model takes, finite values only (`parseBeatZeroTempo`, `parseBeatZeroMeter`, `parseTempoChanges`, `parseMeterChanges`): an unusable entry, or a beat-0 attribute that is present but unusable, is skipped, counted and backed up; an absent attribute is a silent default; an entry at beat 0 that repeats the attributes is logged only; entries out of order are sorted. `TempoChangeEvent`, `TimeSignatureChangeEvent`, `Transport.setTempo` and `TempoEditController.commit` refuse a non-finite value.
